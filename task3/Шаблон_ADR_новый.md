### <a name="_qmphm5d6rvi3"></a>**Решение**
Диграмма контекста приложена в текущей дирректории: C4_context.png, C4_context.drawio
Диграмма контейнеров приложена в текущей дирректории: C4_container.png, C4_container.drawio 

Обоснование решения:
Для рализации основного функционала MVP предлагается сделать два отдельных сервиса на Java силами текущих разработчиков АБС.
Потенциально расчитывать, что это будет части двух микросервисных систем - АБС и Интернет Банк.
Для снижения нагрузки на БД - у каждого сервиса будет своя БД она известной разработчикам MS SQL (не oracle из-за рисков)
### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Использование Kafka для асинхронного подхода к работе с заявкой на депозит с использованием BPMN движка. На текущий момент избыточно в рамках MVP, в дальнейшем можно
Не выделение сервисов в отдельные структуры обяжет докручивать функционал в монолите на C# и Delphi с не поддерживаемыми процедурами. Последнее устаревшая технология и подход может привести к устареванию Банка

**Недостатки, ограничения, риски**

Недостатком текущего решения является то, что текущая команда не имеет экспертизы в микросервисной архитектуре и выделенным разработчикам АБС нужно будет пройти обучение
Ограничением так же является то, что АБС все равно незначительно но придется именять API для процесса персонализированных ставок.
Риски бюджет на MVP может быть выше ожидания бизнеса
